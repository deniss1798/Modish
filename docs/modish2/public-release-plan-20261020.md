# Modish — подготовка публичного выпуска

Следующий срез по жалобе на пустой каталог и интерфейс описан в
[исправлениях от20 октября](catalog-ui-fixes-20261020.md). Пакет9bd0326 ниже
остаётся историческим; он не содержит эти последующие исправления.

20 октября 2026 пользователь выбрал **публичный выпуск**. Белый список
участников и сбор email для закрытой альфы больше не нужны. Это выбор канала,
не подтверждение уже выполненного обновления сервера или публикации APK.

## Артефакт и доступ

Готовим Android release APK. Публикация в Google Play/RuStore и создание
аккаунтов магазинов этим решением не выполняются. Существующий applicationId
сохраняется; произвольная смена package name не используется как обход подписи.

Для выпуска нужна постоянная release-подпись. Запрошено, использовать ли
существующий ключ пользователя или создать новый. Прежний build14 подписан
Android Debug; обычная установка APK с иным сертификатом поверх него требует
отдельного решения о переходе. Ключи/пароли не публикуются и не попадают в Git.
Проверочный debug APK не становится публичным release APK при выборе канала.

В production требуется `CLOSED_ALPHA_ENABLED=false`. Это не снимает обычную
авторизацию персональных данных и операций. Фактическая конфигурация сервера
прочитана после восстановления SSH21 октября: флаг у текущего build14 не задан.
В приватном предложении build15 он явно `false`, JWT и действующий DATABASE_URL
сохранены; предложение пока не активировано. Актуальные доказательства — в
[журнале восстановления каталога](catalog-recovery-20261021.md) и
[плане переключения](build15-production-plan-20261021.md).

## Исправления после выбора публичного канала

- Main Android policy закрывает HTTP; локальные исключения остаются только
  в debug/profile. Release API URL проверяется до транспорта/передачи токена.
- Android backup/transfer не переносит защищённые preferences без ключа
  шифрования. Текущее хранилище и его содержимое при этом не стираются.
- Необязательная генерация визуализации выключена по умолчанию на сервере.
  Без `style_visual_v1` клиент не отправляет запрос. Публичный выпуск не
  включает эту возможность до отдельного контроля квоты/расходов.

Подробные результаты: [Android](build15-public-android.md),
[API URL](build15-public-api-url.md), [генерация изображений](public-AI-safety.md).
Эти изменения требуют нового зафиксированного коммита и повторной проверки.

Пакет из коммита `945435a7d8ae49e2e0b6adbe19b0b02d15bf6905` проверен до
этих исправлений. Он остаётся историческим проверочным артефактом; выбирать
его для публичного deployment вместо нового пакета нельзя. Число тестов
передаётся сборщику явно, чтобы старый default не описывал изменившийся набор.

## До публичного запуска

Нужны: подписанный release APK с проверенными метаданными, свежая копия
рабочей БД и rehearsal миграций/первой сессии на ней, согласованный порядок
maintenance/отката, проверка фактических APP_ENV/доступа/лимитов и свежего
ассортимента, затем приёмка активированного API. Debug/SQLite-проверки
не подтверждают эти внешние этапы. Рабочий сервер пока остаётся на build14.
