# 2.1 — явное согласие на каталог с непроверенным размером

Локальный срез 18 октября 2026; без обновления production и APK.

## Поведение

Каждое новое открытие каталога сначала показывает «Размер не проверен» и
объясняет отличие от персональной подборки. Товары и их фотографии не загружаются,
пока пользователь не нажмёт «Понимаю, показать каталог». «Вернуться» и системная
кнопка назад закрывают экран без запроса каталога.

Согласие действует только в текущем экземпляре экрана, не записывается на диск
и не переносится между аккаунтами. Исходные запрос и категория сохраняются до
подтверждения. Фильтры, поиск, обновление и пагинация работают после согласия.
Все эти обработчики и переход к карточке дополнительно проверяют согласие,
а не полагаются только на отсутствие кнопок. Смена сессии или контроллера
сбрасывает согласие, очищает товары и отменяет применение задержанных ответов.

Входы из профиля, поиска, пустой ленты и незавершённого Style Swipe ведут
через один экран. После подтверждения остаются заметные предупреждения размера
в списке и карточке. Каталог не обучает вкус и не выдаёт вещи за персональные.

API не менялся: это пользовательское согласие внутри приложения, а не новый
серверный механизм авторизации. Отдельные authenticated discovery endpoints
по-прежнему возвращают `not_verified`; строгие пути ленты и образов не ослаблены.
Карточка discovery доступна из уже открытого каталога; отдельного входа в неё
из сохранённого или deep link в текущем приложении нет.

## Проверки

Новые widget tests проверяют отсутствие запросов до согласия, отмену, повторное
открытие, начальные фильтры, смену аккаунта/контроллера и задержанный ответ.
Прежние сценарии каталога проходят через реальное нажатие согласия, сохраняя
проверки поиска, пагинации, ошибок и merchant-size metadata.
Аудит экранов дополнен вступлением и его нижней частью; состояния самого
каталога снимаются после подтверждения. Кнопка согласия допускает перенос строки
при большом шрифте и находится внутри SafeArea/прокручиваемого содержимого.
