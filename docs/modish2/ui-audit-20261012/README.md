# Аудит интерфейса Modish

Проверка начата 12 октября и продолжена 13 октября 2026 года. Последний завершённый проход до закрепления новых production-шрифтов: **71 сценарий, 205 снимков, 0 ошибок layout/widget, 0 ошибок диагностического рендера**. Новые шрифты проверяются отдельным последующим проходом; до него эти PNG не являются доказательством окончательной типографики Android.

`test/new_screen_audit_test.dart` создаёт снимки исключительно из FakeAPI, локальной фотографии и assets проекта. Все запросы изображения завершаются внутри тестового HttpClient, который не открывает сокеты и запрещает другие адреса. Сервер, профиль реального пользователя и каталог не изменяются. Один fixture блузки повторно используется в карточках разных ролей **только для проверки размещения элементов**; качество сочетания настоящих вещей этим не подтверждается.

Матрица: 360×640 и 390×844, верхний отступ 24 px, системная панель Android 48 px. На узком экране проверен масштаб текста 1,3. Для ввода моделируется клавиатурный отступ 280 px. Покрыты splash/welcome, регистрация/вход, onboarding и подтверждение параметров, Style Swipe, Wow, лента и её loading/empty/error, причины рекомендации/отказа, поиск и его состояния, фильтры, запросы shopping intent и их состояния, товары/образы/сохранённое, профиль/параметры, бренды, настройки/помощь, фото/анализ/результат и visual analysis. Прокрутка к нижним действиям проверяется отдельными снимками.

Дополнительные классы PlusScreen, CollectionsScreen и старые RecommendationsScreen/DetailScreen не входят в основной доступный путь приложения: внешних переходов к ним в текущей навигации не найдено. Встроенные старые этапы Intro/FitQuiz всё же включены в диагностическую матрицу как состояния RootScreen.

## Исправленные дефекты

| Подтверждённая проблема | Изменение | Проверка |
|---|---|---|
| Empty feed переполнялся на 20 px при 360×640 / text 1,3 | Высота empty state определяется содержимым; вертикальная прокрутка и центрирование учитывают доступную область | `feed-empty-360-text130.png`, focused widget regression |
| Фотография в короткой ленте занимала около 140 px, название обрезалось до одной строки | Компактный header с доступным запросом, компактная панель пяти действий, название в две строки | `feed-full-360.png`; regression проверяет фото ≥30% высоты экрана и touch targets ≥48 px |
| После shopping intent результата главным содержимым оставалась повторная форма ввода | Компактная сводка условий, явное редактирование и раскрываемое уточнение; результат виден выше | `task-products-360-text130.png`; условия и контекст сохраняются после edit/cancel/refine |
| В образе 5 действий находились в узкой колонке и образовывали длинный вертикальный список | Фотография/описание отдельной строкой; действия занимают всю ширину карточки | `task-outfit-bottom-360-text130.png`; reaction attribution и замена обуви сохраняются |
| Отмена редактирования/новый результат могли оставлять экран прокрученным в прежнее место | Собственный ScrollController возвращает к началу результата | focused edit/refine regression |
| Ответ завершения запроса после ухода со страницы обращался к disposed TextEditingController | Единый `_closeTask` проверяет mounted до работы с полями; refresh после save также пропускается у удалённой страницы | pending-close regression |
| Подписи системы размеров в onboarding обрезались на узком экране | Dropdown-поля выстраиваются вертикально при недостаточной ширине или крупном тексте | `onboarding-preferences-360-text130.png` |

Root отдельно добавил `FeedActionBar.compact` в общий компонент: все действия сохраняют Tooltip/Semantics и область нажатия не менее 48 px. Другой UI-аудитор исправляет safe areas и достоверность результата анализа; их обновления попадают в последующие снимки матрицы.

## Как воспроизвести

```powershell
& C:/src/flutter/bin/flutter.bat test --no-pub test/new_screen_audit_test.dart --reporter expanded
# Быстрый повтор конкретных групп:
& C:/src/flutter/bin/flutter.bat test --no-pub test/new_screen_audit_test.dart --dart-define=AUDIT_SCREEN=feed,task,onboarding --reporter expanded
```

Итог каждого запуска — `audit-results.json`. `contact-01.png` и далее объединяют снимки для просмотра; исходные PNG сохраняются отдельно. В `before/` оставлены пять представительных снимков до исправлений. Частичный запуск заменяет JSON текущей матрицей: для итоговой оценки нужен полный проход.

`compact_screen_regressions_test.dart` содержит пять отдельных поведенческих регрессий; `shopping_task_test.dart` и `intent_outfit_sizes_test.dart` используют устойчивые ключи выбранной роли вместо зависимости от расположения вложенных Row. **32 targeted tests прошли** в `.tmp/new-screen-functional.log` вместе с activation/optional refusal. Полный визуальный проход прошёл в `.tmp/new-screen-audit.log`.

До перехода на production-assets шрифта снимки загружали Windows Arial/Georgia, а для null font family в RenderParagraph применяли только при capture Arial, чтобы не показывать квадратный Ahem шрифт Flutter tester. Ошибки реальных widgets собирались **до** этой диагностической подстановки; её ошибки записаны отдельно. Подстановка и фотографический fixture обозначены в JSON. Она не доказывает точную геометрию или растеризацию системного шрифта Android.

Следующий обязательный контроль — снимки с закреплёнными Inter/Playfair Display из assets и проверка на Android: системная навигация/клавиатура, разрешения камеры/галереи, реальная сессия/поиск/merchant links и настоящие доступные SKU. Автоматические снимки не заменяют эти проверки и не означают, что продуктовые ограничения каталога уже сняты.
