# 1.4 — максимум три полных честных образа

Локальный срез 16 октября 2026; без production deployment.

Автоматические подборки ограничены тремя образами на сервере и в UI. Режим
«Все» запрашивает по одному для daily/office/evening, а не трижды по три.
WOW и Intent ограничивают также старые сохранённые snapshots в ответе; сами
snapshots, библиотека сохранённых образов и её счётчики не урезаются.
Обычный `/outfits` ограничивает текущую выдачу после проверки фактов;
`saved_only=true` сохраняет библиотеку целиком в пределах прежнего API-лимита.
Pending не показывает старые карточки как новый готовый результат. Пустая
выдача явно сообщает об отсутствии подходящих полных образов.

Клиентская legacy-модель также перестала дорисовывать четыре вещи, палитру,
обоснования и альтернативы при отсутствующих данных. Реальные строки товаров
сохраняются; `one_piece` подписан как «Платье / комплект». Неподдерживаемый
исторический JSON обрабатывается безопасно и не превращается в новую рекомендацию.

## Качество и бюджет

Для любого персонального комплекта подтверждается общий бюджет Fit, включая
старых пользователей без ActivationSession. Сумма с копейками не может
превышать этот бюджет; неизвестный/нулевой бюджет не подтверждает комплект.
Это намеренное усиление политики 1.4: историческая legacy-граница
`бюджет × число вещей × 1,05`, сохранённая в срезе 0.4, больше не применяется
к полным образам. Политики отдельных товаров ленты и дополнений не изменены.

Legacy fallback требует верх + низ + обувь, точные размеры, совместимость,
сценарий и SourceRule, включая аварийный raw-каталог. Отсутствие альтернатив
оставляет существующие записи; неполный комплект не подменяет их.

## Старый формат API

`/recommendations/generate` больше не создаёт текстовые шаблоны без товаров.
Сохранён формат Recommendation JSON, но `items` и `items_v2` содержат названия,
цены и ссылки реальных прошедших проверку SKU; есть `product_ids`.
Подбор использует read-only prepare и общую короткую публикацию. Внутри неё
повторно проверяется квота; реальные Outfit/Recommendation, ротация и списание
коммитятся вместе. Пустой результат не расходует квоту.

Старые SKU-less шаблоны остаются в БД, но не выдаются как подходящие образы.
Исторические реальные рецепты заново проверяют наличие, размеры, сценарий и
текущую сумму. Сохранённая библиотека не ограничивается тремя записями.

## Проверки

Есть границы до/после одной копейки, отсутствие части комплекта, raw SourceRule,
спортивные брюки в офисе, старые snapshots из пяти валидных образов, сохранение
старых записей при нехватке вещей, UI count/empty/pending/library regressions.
