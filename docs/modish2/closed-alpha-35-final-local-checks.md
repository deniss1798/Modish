## Весь backend с PostgreSQL без пропусков

Полный набор **936/936** прошёл за **257,557 с**, без пропущенных тестов.
В нём выполнены все **55** PostgreSQL-сценариев из 13 модулей: revision,
feed, Intent create/feedback/mutation/outfits, поиск/дополнения, Style Swipe,
WOW, обычные/legacy образы, фото-квота и причины отказов первых 20 карточек.

Раньше эти сценарии принимались отдельными срезами. Последний общий запуск
через `scripts/check_backend.py` пропускал их: этот безопасный SQLite runner
намеренно очищает окружение, включая `MODISH_ISOLATED_PG_RUNTIME`.
Пропуски не означали 55 ранее непроверенных функций; новый запуск подтверждает
совместную работу всех сценариев на текущем дереве.

Для приёмки использован отдельный Python-процесс с очищенным окружением,
отключённым dotenv и явным `MODISH_ISOLATED_PG_RUNTIME` на
`.tmp/alpha12-pg-runtime.json`. Основной app engine остаётся SQLite в памяти,
а opt-in tests подключаются к изолированному PG на `127.0.0.1:55439`.
До discovery проверены фактические `SHOW data_directory` / `SHOW port`
и отсутствие старых fixture schemas. Каждый PG-test дополнительно проверяет
сервер перед созданием собственной UUID-schema через `isolated_postgres.py`.

После набора осталось **0** fixture schemas; кластер остановлен,
`postmaster.pid` отсутствует. Служба на 5432 не использовалась.
Лог исключён из Git:
`.tmp/closed-alpha-all936-with-postgres-20261019.log`.

## Настоящее сохранение параметров на Android

Дополнен существующий реальный Flutter → HTTP journey. После регистрации,
15 оценок, WOW, ленты, сохранения товара, поиска и явного согласия на каталог
пользователь через меню открывает «Параметры подборки», меняет рост 170→171,
скрывает клавиатуру и нажимает «Сохранить».

Проверка требует одновременно:

- успешный настоящий PATCH `/fit-profile/me` с ответом 171;
- последующий GET с 171 и обновлённое значение в AppController;
- закрытие формы без ошибки;
- повторное открытие формы через меню с видимым 171;
- доступный hit target кнопки и её нижнюю границу выше фактического
  системного inset при закрытой клавиатуре.

На Pixel 9a с трёхкнопочной навигацией inset равен **48 logical px**.
Сохранение с обновлением данных заняло **1,330 с**. Весь расширенный journey
прошёл за **50 с**. Это измерения одного debug-прогона на синтетическом
каталоге, включая ожидания теста, а не production p95.

Driver теперь сохраняет **пять** PNG: добавлен `profile-parameters.png`
перед сохранением. Все пять просмотрены: фото загружены, переходы завершены,
кнопки и предупреждения читаемы; явных наложений/overflow не найдено.
SDK PNG не рисует системные кнопки Android; отступ проверен также геометрически
по реальному `viewPadding` эмулятора.

Артефакты исключены из Git:
`.tmp/device-alpha-artifacts/20261019T201935285210Z-32c6ed3eac4d4c28a5125d5981d5bf38/`.
В `journey.json` сохранены `profile_parameters_saved_and_reopened=true`,
inset, замеры этапов и счётчики путей запросов. Токенов, паролей, тел API
и PNG-байтов в JSON нет. Настоящий HTTP и запрет внешних запросов сохранены;

## Что завершено и что отложено

Кодовые пункты ТЗ и согласованные локальные проверки завершены.

неподтверждённые обувные системы доступны только в каталоге с согласием,
не допускаются в персональную ленту и образы.

Синтетическая приёмка не подтверждает свежесть рабочего ассортимента,
правильность его фотографий или наличие размера в checkout. Готовность
реальных инвайтов не объявляется доказанной этим стендом.
Сервер, рабочая БД, GitHub и пользовательский APK не обновлялись.
