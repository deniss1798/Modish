# Shopping Intent: продолжение 10 октября 2026

Рабочий API остаётся build13. Нового APK нет. Полное ТЗ и выпуск пока не завершены.

## Проверенные изменения v20

- Однократный разбор атрибутов Product DNA, сохранение provenance/конфликтов и отделение семантики от commerce snapshot. Скоринг читает только обученные признаки и нужный контекст.
- Оценки 50 финалистов каждой категории сохраняются после полного прохода каталога: ограниченный request-cache не заставляет повторно ранжировать ранние результаты.
- Чтение подтверждённого размера не копирует весь Fit. Изменение/сериализация профиля сохраняют защиту от общих mutable ссылок.
- UK `7,5` не превращается в размеры 7 и 5; повторные CSV-поля сохраняют конфликт систем; `Size System` читается; `available` и `in_stock` согласуются.
- Полный точный пакет: 186 файлов, 302 теста локально и в Docker; положительные PostgreSQL-сценарии пройдены. Миграции не менялись.

На реальном каталоге измерены три последовательных запуска одного LETTER L-профиля после настоящих 15 Style Swipes, 0,75 CPU / 768 МБ. Во всех сравнениях совпали колода и первая лента (20/20), WOW выдавал 0 образов.

## Свежая копия каталога

После 72 часов старые наблюдения источников перестали быть свежими. Новые четыре фида скачаны заново через разрешённые сохранённые настройки, до 256 МБ каждый; в рабочую БД запись не выполнялась.

Первый импортёр был остановлен Docker OOM (exit 137) при полной загрузке ORM-карточек. Хеш всех test products совпал с состоянием до импорта, новых stock timestamps не было. Исходные журналы сохранены. Повторный helper читает CSV по строкам, а для проверки идентичности загружает только source/external_id/id; 13 safety-тестов и сравнение CSV quoted-newlines/размеров пройдены.

Повторный импорт 67 791 строк четырёх источников зафиксирован одной транзакцией, существующие ID сохранены. Наблюдения датированы фактической загрузкой. Перед обоими импортами создан и проверен pg_dump тестовой БД. Audit десяти профилей завершён, синтетические записи откатились; изменения вне четырёх источников и рабочего API не выполнялись.

- 204 894 stored products; 54 005 свежих доступных SKU.
- 5 LETTER-профилей XS/S/M/L/XL: настоящие 15 свайпов, 20 карточек первой ленты каждому; outerwear XS 16, остальные 20.
- 5 RU-профилей 42/44/46/48/50: подходящей стартовой колоды нет.
- 40 intent-запросов: 100 товаров, 0 недопустимых результатов, 0 полных образов. Все запросы parser поддержал.
- 9 452 свежих обувных SKU имеют доступный size token, но `size_system_unknown`; обувь во всех десяти фильтрах — 0. Причину единиц не смешиваем с отсутствием stock signal.
- Ворота реального каталога не пройдены; успешные unit-тесты этот результат не отменяют.

Отчёты: `intent-v20-fresh-retry-20261010-refresh-report.json`, `intent-v20-fresh-retry-20261010-readiness-report.json`, `intent-v20-fresh-retry-20261010-inventory-report.json`.

312 тестов Docker и положительные PostgreSQL-сценарии пройдены. ## Незавершённые условия

1. Подтверждённые единицы размеров источников для обуви и числовой одежды. Старый полный inventory обуви уточнил причину: 9 351 числовой token с `size_system_unknown`, а не отсутствие product stock signal.
2. Реальные полные комплекты и ручная визуальная проверка.
3. Окончательные реальные измерения и устранение оставшихся задержек.
4. Согласованный выпуск API/APK после выполнения проверок каталога.

Официальные таблицы CAPRICE/BAON сами по себе не определяют смысл поля экспортного фида: область доказательств описана в `official-size-contract-research-20261009.md`. Массовая RU/EU/LETTER-конверсия не включена.
