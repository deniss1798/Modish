# Контракт аналитики Shopping Intent — v17

События записывает сервер в той же транзакции, что и действие. Поле запроса, размеры тела, текст уточнения и credentials не входят в MetricEvent. Разрешены идентификаторы, тип/версия задачи, тип действия/причины и агрегаты допуска.

| Имя из ТЗ | Когда записывается | Что означает |
| --- | --- | --- |
| intent_created | Создание нового ключа запроса | Новый intent, не повтор HTTP |
| intent_updated | Уточнение, персональная причина или успешная замена | Версия текущего запроса изменена |
| intent_completed | Явное «Готово» | Пользователь завершил задачу; не покупка |
| intent_abandoned | Явное «Новый» | Отказ от текущей задачи; выход с экрана не считается отказом |
| recommendation_explained | Фактический view результата с объяснением | Объяснение предоставлено с просмотренным результатом; не проверка чтения текста |
| outfit_generated | Выдан полный комплект | Доставка, не показ |
| outfit_saved | Первое успешное сохранение данного комплекта | Повтор сохранения не пишет второе событие |
| outfit_item_replaced | Успешная замена части | Ссылка на исходный комплект, остальные части сохранены |
| size_filtered | Новая генерация версии задачи | Агрегаты size_checked/size_passed до ranking |
| availability_filtered | Новая генерация версии задачи | Каталог в области пола/категорий и количество свежих доступных товаров |
| brand_affinity_updated | Принято новое поведенческое свидетельство бренда | Вход read-derived Brand Profile изменился; численное значение affinity может остаться прежним после дедупликации |
| reason_dislike | Принята необязательная причина | «Дорого»/«не для задачи» могут менять только текущий intent |

Дополнительные диагностические события: intent_parsed, intent_feedback, intent_results_generated, intent_product_viewed.

Ранее записанные intent_refined, intent_outfit_saved, intent_outfit_item_replaced читаются через алиасы. Новые события не записываются дважды под старым и новым именем.

## Знаменатели

- intent_funnel: уникальные задачи, созданные за окно 1–90 дней. Действия другого владельца исключены. Существующие ключи outfit_save_rate и replace_rate здесь сохраняют значение конверсии **задач**, не комплектов.
- recommendation_funnel: уникальные пары intent/product с фактическим view либо явным действием. Предзагруженные результаты не являются exposure. Like, Save, Dislike, Open Product и Affiliate Click делятся на этот знаменатель.
- outfit_funnel: уникальные пары intent/outfit, для которых сервер записал outfit_generated. Показ устанавливается по view части выбранного комплекта либо явному действию с комплектом. Сохранение, подтверждённое открытие продавца и замена делятся на **exposed_outfits**. Переход по SKU не приписывается всем комплектам, содержащим этот SKU.
- AvailabilityPassRate: свежие доступные товары / каталог в области текущего пола и категорий до фильтра цены.
- SizePassRate: прошедшие exact size / реально проверенные кандидаты после SQL-допуска по stock/budget/gender. Для outfit проверка может остановиться на отсутствующей обязательной части; это не показатель всего каталога.
- InvalidRecommendationRate: невалидные SKU / уникальные SKU доставленной версии intent. Последующее изменение магазина не делает исходную доставку ошибочной.
- Пустой знаменатель возвращает null, не 0 и не 100%. Повторный POST с тем же ключом не создаёт новую генерацию и не увеличивает знаменатель качества.

Клиент передаёт intent_outfit_id только для выбранного комплекта. Сервер проверяет владельца, версию, наличие комплекта в текущих результатах и принадлежность вещи этому комплекту. Для перехода к продавцу событие affiliate_click подтверждается успешным открытием внешнего приложения; URL-запрос и покупка отличаются от такого события.

Проверки v17: сценарии повторных view/save, пустых знаменателей, forged owner/outfit, Product DNA/Taste, idempotency и ограничения экрана пройдены. Реальная каталоговая проверка не доказывает пользовательские CTR или качество вкуса.

В v19 добавлено объединение reason_dislike с действиями текущего intent: «дорого»/«не для задачи» учитываются в Dislike Rate по product_id без обучающего RecommendationEvent. Персональная причина, записанная также в RecommendationEvent, не считается дважды.
