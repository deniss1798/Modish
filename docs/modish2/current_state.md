## Выбранный продуктовый сценарий

Пользователь выбрал **женскую повседневную одежду**. Магазин первого проверяемого источника, география доставки и фактическая гранулярность его предложений ещё требуют определения. Москва не подставляется автоматически. Выбор сценария не доказывает наличие достаточного каталога или спроса.

## Карта работающего кода

- Flutter: `lib/app.dart`, `AppController`, `RootScreen`, существующие экраны onboarding, ленты, образов, сохранений и профиля. Сетевой слой — `lib/core/network/api_client.dart`. В текущем refresh есть товарный `/feed` и вторичный `api.feed()` с legacy-разбором: F11 остаётся открытым.
- API: FastAPI в `backend/app/main.py`; группы auth, products/feed, recommendations/events, profile, fit-profile, onboarding, taste-profile, outfits, affiliate, catalog-admin, analytics, media-proxy. Инвентарь деклараций — [api_inventory.md](api_inventory.md).
- Данные: SQLAlchemy `backend/app/models.py`; User, StyleProfile, ProductSource, Product, CatalogSyncRun, SourceRule, AffiliateClick, TasteProfile, UserTasteFeature, RecommendationEventV2, FitProfile, Outfit, ProductImpression, UserProductState и вспомогательные модели. Product пока хранит legacy `price` в целых рублях; Money DTO ещё не реализован.
- Импорт: Admitad/Befree XML/YML/CSV → mapper → normalizer → upsert. Проверка полноты снимка отсутствует; автоматическая деактивация остаётся дефектом F08.
- Рекомендации: retrieval → фильтры → MIE → diversity; `ranking_v4`, `mie_phase7_outfit_engine_v2`, hash embeddings, Outfit Engine v2 с legacy fallback. Новые intent capability и общий commerce gate пока отсутствуют.
- Источники: в коде 11 пресетов Admitad, конфигурация Befree и demo. Реальный состав ProductSource, включённость, свежесть и наличие в production неизвестны.
- Deployment: Docker/PostgreSQL, резервная копия, восстановление, миграции и возврат приложения проверены в D00. Новый API запущен из проверенного image; HTTPS обновлён.

## Выполненный пакет T00 / T01

T00: зафиксированы версии, карта кода, baseline, [реестр F01–F27](issues.md) и выбор сценария. Остальные выводы документа относятся к тому же исходному дереву; не все исторические воспроизведения повторены в этой сессии.

T01, локальная часть:

- Удалены встроенный ключ из `.env.example` и персональные параметры Admitad из пресетов. Новые значения не добавлялись в `.env`.
- Пресеты содержат публичные идентификаторы, URL собирается по запросу из проверяемой конфигурации; отключённая интеграция не требует credentials и не мешает импортировать приложение.
- Bootstrap отклоняет отсутствующую/невалидную конфигурацию до изменений БД и не возвращает credential-bearing URL в своём результате.
- В production проверяются обязательные DATABASE_URL/JWT_SECRET; интеграции AI остаются необязательными для базового запуска.
- Добавлено маскирование URL-параметров и provider keys в корневых обработчиках логов и сообщениях ошибок импорта. Это целевая защита известных форматов, а не универсальный DLP.
- Добавлены изолированный запуск серверных тестов и CI-проверка известных форматов секретов.

## Как повторить проверки пакета

Из корня, используя Python виртуального окружения backend:

```powershell
& backend/.venv/Scripts/python.exe scripts/check_backend.py
& backend/.venv/Scripts/python.exe scripts/scan_secrets.py
& backend/.venv/Scripts/python.exe scripts/scan_secrets.py --history
git diff --check
```

Runner очищает конфигурацию приложения, сохраняет только системные пути временных файлов и блокирует загрузку dotenv. Он не запускает PostgreSQL или внешние фиды. Для history scan код возврата 1 ожидаем при сохранённой истории утечки. Отчёт содержит только commit, путь, строку и тип.
