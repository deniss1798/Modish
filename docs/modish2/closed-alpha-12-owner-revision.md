# 1.2 — подготовка коротких транзакций: ревизия входных данных

15 октября 2026. Исторический промежуточный срез `a53d572`, **весь пункт 1.2 ещё не закрыт**.
Продолжение: [HTTP feed разделён на prepare/publish](closed-alpha-12-feed-publication.md).
Ниже состояние и доказательства на момент `a53d572`.
Тяжёлое ранжирование пока сохраняет прежнюю блокировку; преждевременно снимать
её без полного протокола публикации нельзя. Production и APK не менялись.

## Подготовлено

Добавлена `User.recommendation_revision` и аддитивная миграция 0028. Общая
owner mutation блокирует владельца, обновляет ранее загруженные личные строки
и атомарно увеличивает ревизию SQL-выражением. Вложенные helpers используют
тот же контекст; изменения coalesce в пределах SessionTransaction. Rollback
и savepoint не оставляют успешную ревизию. Реальные данные не выводятся в лог.

Малый профильный граф сравнивается по смысловым данным; audit clocks и выдача
карточек не считаются вкусом. Для истории и признаков есть явная регистрация
принятого изменения, включая случай, когда необязательный feature writer
ничего не изменил. Вложенные профильные scopes повторно граф не читают.

Подключены:

- PATCH параметров пользователя, Fit, Taste, style profile и style target;
- создание отсутствующих Style/Taste/Fit с повторной проверкой под блокировкой;
- шаги и фото-подтверждение онбординга, configure, swipe feedback, completion;
- product feedback, прямое обновление User Twin и persisted decay;
- фактические первые просмотры и завершение принятого фото-анализа;
- legacy feedback. Изменение профиля и пересборка его summary атомарны.

Сохранённый повтор save, повтор фото и идентичный PATCH не дают лишнюю ревизию.
Delivery ids, deck ids, WOW allocation и повтор view той же карточки не создают
нового первого просмотра. Для изменяющих Intent операций установлен порядок
owner → Intent; их тяжёлая генерация пока не преобразована.

## Проверки этого среза

- Полный backend: **635 тестов**, 57,266 с, OK; 3 opt-in PostgreSQL теста
  пропущены в стандартном SQLite запуске.
- Все 3 PostgreSQL теста выполнены отдельно на новом временном кластере18.3:
  два соединения, ожидание owner lock, обновление заранее закешированного
  профиля после ожидания, rollback/retry и реальная миграция 0028 — OK.
- Кластер размещался в workspace `.tmp`, слушал только 127.0.0.1:55439;
  перед любым schema write тест сверял `SHOW data_directory`. Изменял только
  сгенерированную schema. После проверок временный кластер остановлен;
  существующая служба PostgreSQL не использовалась.
- SQLite tests покрывают вложенность, no-op, rollback/savepoint и миграцию.
  Матрица API/онбординга/истории/просмотров/decay — 7 тестов, OK.
- Батч признаков остаётся ограниченным постоянным числом запросов: максимум6
  SELECT вместо прежних3, с общей owner reload/creation recheck. Убрана лишняя
  проверка четырёх профилей при создании одного Taste. Нет SELECT на каждый
  обучаемый признак. Проверки rollback и duplicate save сохранены.
- Flutter analyze: No issues found, 3,6 с; Flutter в этом срезе не менялся.

Это **не** тест неблокирующего ранжирования: проверен пока протокол изменений.
Остаются аудит прямых maintenance/tag writers, отделение read-only подготовки
от публикации, финальная проверка версии/товаров/правил, bounded retry и
конкурентный тест: feedback завершается до снятия барьера долгого ranking.
Идемпотентность pending Intent требует отдельной явной реализации.
