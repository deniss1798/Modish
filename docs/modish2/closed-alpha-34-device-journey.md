# Закрытая альфа: первая сессия Flutter → HTTP → БД

Локальное продолжение от 19 октября 2026. Дополняет приёмку кодовых пунктов,
но не заменяет проверку рабочих товаров на физическом телефоне.

## Исправленная ошибка

У нового пользователя список возможностей сервера терялся при сохранении
параметров. Ответ WOW также содержал неполный список: из него исчезали каталог
и режим подбора. Поэтому после первой сессии эти входы могли отсутствовать
до повторного входа, хотя сервер их поддерживал.

`recommendation_capabilities.py` теперь задаёт один контракт для status,
preferences и WOW. Flutter сохраняет уже подтверждённые возможности при
замене ответов пользователя и принимает новый список WOW как авторитетный.
Старые completed/rated при этом не переносятся в новые параметры.

Регрессия проверяет сохранение возможностей на шаге параметров и возможность
серверу убрать ранее объявленную функцию. Реальный HTTP-тест проверяет полный
непустой путь status → preferences →15 реакций → WOW → status.

## Изолированный стенд

`scripts/run_device_fixture.py` поднимает настоящий FastAPI на
`127.0.0.1:8773`. Это новая SQLite-база с синтетическими карточками,
а не копия рабочей базы:64 товара восьми категорий имеют подтверждённый
LETTER M / EU38; ещё одна обувная карточка имеет UNKNOWN и доступна только
в отдельном каталоге. У каждого запуска новая папка UUID внутри `.tmp`.

До любого импорта приложения сценарий очищает унаследованные настройки,
отключает dotenv, задаёт тестовый JWT и белый список синтетического email.
Внешние сокеты и DNS запрещены. Изображения 65 известных URL обслуживаются
локальным JPEG; неизвестные URL отклоняются. Рабочие media/SSRF правила
не ослаблены. Ни магазины, ни production API не нужны для этого стенда.

Три проверки запускают стенд в новых процессах: проверяют изоляцию окружения
и БД, запрет внешней сети, локальные изображения, точный bind и HTTP-контракт
первой сессии с непустым WOW. Повторное использование уже импортированного
приложения запрещено.

## Настоящий интерфейс на Android

`integration_test/local_first_session_test.dart` использует настоящие
AppController/ApiClient/Dio, HTTP, native secure storage и Flutter UI.
FakeApi и подменённого транспорта нет. Перед регистрацией проверяются
явный локальный адрес, режим image proxy и положительный маркер стенда.
Тестовый HttpOverrides сохраняет настоящий HttpClient, но допускает только
этот origin до DNS/соединения. Даже резервная загрузка картинки с CDN
при отказе локального proxy не может выйти во внешнюю сеть.

Сценарий проходит регистрацию, параметры,15 подтверждённых лайков, WOW,
ленту, сохранение и вкладку сохранённого, поиск с открытием карточки,
профиль, явное согласие на каталог и карточку UNKNOWN-размера. До согласия
нет запроса каталога; UNKNOWN не попадает в Style Swipe и персональную ленту.

Прокрутка выполняется настоящими жестами; перед нажатием элемент должен
проходить hit test. Промахи фатальны. Ограниченные ожидания не используют
неограниченный pumpAndSettle. SDK driver сохраняет четыре PNG и небольшой
JSON с измерениями, не записывая токены, пароли или тела ответов.

Для повторения нужен **временный эмулятор**: тест очищает защищённое
хранилище приложения. В этой приёмке Pixel 9a запущен с
`-read-only -no-window -no-snapshot -no-audio -no-boot-anim -port 5558`,
изменения его системной навигации и установки остаются во временном слое.
Физический телефон не подключён. Включена трёхкнопочная навигация.
Для окончательного прогона `-data` указывает на новый userdata-образ внутри
`.tmp/device-alpha-avd-<UUID>`, созданный из начального qcow2 образа AVD,
а не из его пользовательского overlay. Старый диск был почти заполнен;
на новом перед установкой свободно 4,8 ГБ. `-dns-server 127.0.0.1` отключает
обычное внешнее разрешение имён внутри эмулятора. Временный диск после
приёмки удаляется; исходный AVD не сбрасывается.

В отдельном процессе запустить стенд, затем из корня проекта:

```powershell
& backend/.venv/Scripts/python.exe scripts/run_device_fixture.py
```

```powershell
& C:/src/flutter/bin/flutter.bat drive --no-pub -d emulator-5558 `
  --driver=integration_test/local_driver.dart `
  --target=integration_test/local_first_session_test.dart `
  --dart-define=MODISH_API_BASE_URL=http://10.0.2.2:8773 `
  --dart-define=MODISH_IMAGE_PROXY=true
```

Перед каждым новым прогоном перезапустить стенд: учётная запись и реакции
предыдущего прогона намеренно не сбрасываются через HTTP. Сам стенд не
запускается автоматически вместе с рабочим API.

Добавлена только dev-зависимость `integration_test` из установленного
Flutter SDK и её транзитивные инструменты. Она нужна для отсутствовавшей
проверки настоящего приложения против HTTP; runtime-зависимости не менялись.

## Границы приёмки

Одинаковый локальный JPEG намеренно используется для всех синтетических SKU:
снимки доказывают расположение элементов и прохождение пути, а не эстетическое
качество сочетаний или правильность изображений рабочего каталога.
Один debug-прогон на SQLite/эмуляторе не является production p95.
Read-only режим относится к команде запуска AVD, а не к любому Android-устройству.

Пункт 2.3, наличие размеров в checkout и готовность рабочего каталога остаются
внешними проверками. Сервер, рабочая БД, GitHub и пользовательский APK
в этом продолжении не обновляются.
