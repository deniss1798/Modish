# 1.1 — качество первой сессии

15 октября 2026. Только код и изолированный каталог; production не изменялся.

## Исправления

- Сохранённая Style Swipe колода повторно проверяется по текущим SourceRule,
  как и свежая загрузка. Новое ограничение магазина убирает старую карточку.
- Перед новой like/dislike повторно проверяются размер, пол, цена, наличие,
  категория, ссылки и правила источника. Изменившаяся вещь получает 409 без
  обучения вкуса и увеличения счётчика. Повтор уже принятой оценки идемпотентен;
  `unavailable` по-прежнему позволяет убрать карточку без обучения.
- Неизвестная/пустая валюта не подставляется как RUB.
- Общая проверка URL отвергает неверные порты/хосты, userinfo, embedded whitespace,
  управляющие символы, backslash, локальные и непубличные IP, нестандартную запись
  IPv4 и локальные суффиксы после IDNA-преобразования. Сохраняет обычные HTTP(S),
  публичные IPv4/IPv6, IDN, encoded path/query и разворачивание партнёрских ссылок
  на конкретную карточку. Некорректная ссылка также отправляет импорт в карантин.
- Flutter объясняет изменение карточки и предлагает «Обновить подборку»;
  действие не повторяет прежнюю оценку.

## Независимая сквозная проверка

Три профиля: XS/economy 4 000, M/mass 10 000 и L/mid 25 000 рублей.
Для каждого — 75 заранее помеченных положительных и 93 отрицательных SKU.
Expected-set не использует проверяемые size/eligibility/URL/classification helpers.
Проверены configure → 20 Style Swipe карточек → 15 сохранённых like events →
завершение → 20 сериализованных API feed карточек → 20 реальных view exposures.
В выдаче нет SKU из отрицательного множества, есть непустые положительные
результаты; impressions используют `first_session_feed`.

Отрицательные примеры включают противоположный/неизвестный пол, точный размер
отсутствует, неизвестные/неверные обувные единицы, ребёнка, косметику, подушку,
спорт/luxury, невалидные фото/ссылки, устаревшее/отсутствующее наличие и цену
на 0,99 рубля выше бюджета. Граничные 300,00 и верхний бюджет доказаны как
допустимые в пуле, независимо от того, выбрало ли их ранжирование в конкретные20.
NULL currency отдельно проверяется в памяти после flush, чтобы ORM default
не скрыл проверяемый случай; пустая валюта включена в общий отрицательный пул.

Ещё проверены изменение уже выданных карточек, refill, новый SourceRule,
дефицит Style Swipe, исчерпание, короткая первая лента, явный фильтр и пустая
выдача. Дефицит не ослабляет hard gates; diversity fallback использует только
прошедший admission пул.

## Границы проверки

URL-проверка на этапе ранжирования синтаксическая и не выполняет DNS/HTTP для
каждого товара. Она не доказывает текущую доступность магазина/CDN или checkout.
Серверный download отдельно проверяет и закрепляет публичный DNS/IP перед
соединением; Flutter обрабатывает недоступное фото. Доступность реальных ссылок
и достаточность рабочего каталога не подтверждены синтетическим набором.
Скорость production и проверка на физических телефонах сюда не входят.
