# Регулярное обновление каталога: выпуск17

Рабочий выпуск16 опубликован 29 октября; его APK и HTTP-проверки закреплены
в `build16-deployment-record-20261029.json`. Этот документ описывает следующий
backend-выпуск. Наличие файлов service/timer в Git не означает их установку.
Фактическое включение фиксируется отдельным отчётом развёртывания.

## Устройство

Одна история Alembic: `20261015_0028` → `20261028_0029`. Новая таблица
`catalog_refresh_runs` зарегистрирована в общей ORM metadata. Предыдущие
31 таблица, включая `alembic_version`, сохраняются; после миграции их32.
API следующего пакета — `1.0.3-build17`. Клиент Android build16 совместим,
его исходники и постоянная подпись для этого backend-изменения не меняются.

Подготовка скачивает четыре сохранённых HTTPS-экспорта Admitad. URL доступа
остаются в памяти. Ограничения: 256 МиБ на источник и 600 секунд на всю
сетевую загрузку. Манифест содержит хеши байтов и реальные времена начала
HTTP-запросов; чтение старого CSV не создаёт нового наблюдения наличия.
DNS и TLS привязаны к публичному адресу `export.admitad.com`, перенаправления
и системные прокси не используются.

Согласованный read-only снимок читает конфигурации, правила, полные отпечатки
товаров/записей и предыдущие успешные счётчики. ORM-потоки удерживают только
дескрипторы идентичностей и хеши. SQL-транзакция закрывается до нормализации.
Подготовленный SQLite-файл запечатывается с полным SHA256. Четыре источника
и правила размеров остаются прежними; неизвестные размеры не подтверждаются.

Публикация использует один PostgreSQL connection с session advisory lock,
короткие транзакции до25 операций/1 МиБ и прежние строгие проверки источника,
правил и строк. Курсор, счётчики и изменения товаров фиксируются атомарно.
План COMMIT записывается на диск до начала каждого пакета. После потери
подтверждения следующий процесс сначала разрешает исход по durable ledger.
Ограниченные повторы допустимы для известных SQL-конфликтов; изменившиеся
строки и расхождение состояния требуют разбора.

Порог потери сравнивает полные входные снимки, а не всю накопленную историю:
не менее50% предыдущего объёма и80% доступных качественных товаров.
Успешный ledger хранит измеренные `total_received`, `distinct_received` и
`available_quality` для следующего запуска. До первого нового полного запуска
используются проверенные фиксированные нижние пороги и последний публичный
успешный счётчик; отсутствующие показатели не угадываются по Product.

## Расписание и восстановление

Host supervisor устанавливается в `/opt/modish/scripts/catalog_refresh17_host.py`.
Его частная конфигурация — `/etc/modish/catalog-refresh17.json`, режим0600.
Она закрепляет image ID, commit, archive SHA, Docker network ID, SHA частного
env-файла и единственный рабочий каталог `/var/lib/modish/catalog-refresh17`.
Env содержит фактическое подключение worker к PostgreSQL; значения доступа
не должны попадать в Git или журнал. Схема29 и точный образ проверяются
до запуска задания. Host не применяет миграции.

Service запускает изолированные контейнеры подготовки и публикации с одним
рабочим bind mount, read-only rootfs, одним CPU, 1536 МиБ RAM,128 PID,
без опубликованных портов и дополнительных capabilities. Wrapper сохраняет
create/start intent и точную идентичность контейнера. При ошибке или остановке
service завершает только проверенный принадлежащий ему контейнер.

Timer планируется на00:00 и12:00 по часовому поясу сервера с задержкой
до15 минут и `Persistent=true`. Одновременные запуски запрещены flock.
Сроки подготовки и публикации сохраняются на диск и не продлеваются
перезапуском. Хранятся пять проверенных завершённых каталогов запуска;
неизвестные и незавершённые артефакты автоматически не удаляются.

Прерванная публикация останавливает автоматическое создание следующей.
Причина видна в состоянии systemd и JSON-ответе host. Оператор использует
тот же supervisor с `--phase status`, затем `--phase resume` либо
`--phase abandon --reason-code snapshot_expired`, передавая существующий
`--run-id`. Подтверждение COMMIT разрешается до продолжения или отказа.
Срок годности72 часа можно пропустить только при чтении статуса/явном
отказе; это не разрешает публиковать устаревшие строки и не меняет их время.
Отменённый запуск нельзя возобновить; новая HTTP-попытка получает новый UUID.

Downgrade29 запрещён при работающем worker или незавершённом ledger. Нельзя
удалять checkpoint или восстанавливать всю старую базу поверх новых действий
пользователей. Ошибки регулярного обновления не закрывают работающий API.

Локальный общий прогон:1123 теста,74 пропуска в SQLite-режиме. Отдельно все
72 проверки на собственном PostgreSQL прошли без пропусков. Две проверки

До установки расписания остаётся Linux/Docker-обкатка неизменяемого пакета
на новой согласованной копии реального каталога, включая конкурентные
API-чтения, время удержания блокировок, CPU/RSS и восстановление задания.
Результат и установленное расписание должны быть закреплены фактическими
отчётами, а не только наличием этого документа.
