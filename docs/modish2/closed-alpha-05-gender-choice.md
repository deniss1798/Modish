# 0.5 — пол только после явного выбора

15 октября 2026. Только код и изолированные проверки. Сервер и APK не обновлялись.

## Поведение

`FitProfile.gender_target` допускает NULL и больше не имеет Python/DB default.
Создание профиля, его чтение, размеры, стили и результат анализа фото не
подставляют мужской, женский или универсальный гардероб.

Старая анкета и редактор параметров открываются без выбранной кнопки, если
выбора нет. Новый онбординг сохраняет фокус на женском гардеробе, но требует
явного нажатия «Женское». Указанный ранее пол восстанавливается из профиля.
Клиент не выводит пол из ошибки/пустого ответа и не переносит его из прошлого
аккаунта. Передача параметров до регистрации также не подставляет мужской пол.

NULL/unknown закрывает персональные feed, MIE, legacy, Intent, WOW и дополнения
до ранжирования. Статус возвращает `gender_target: null`, причину `gender`
и необходимость подтверждения. Legacy generation отклоняет запрос до списания
квоты; сохранённая история остаётся в базе. Каталог без выбора не предполагает
женскую аудиторию: возвращает пустую страницу с `gender_basis: missing`.

Явный выбор menswear/womenswear/unisex сохраняется в старых совместимых путях.
Новая активация по-прежнему предназначена для womenswear; другой выбор честно
отклоняется и не перезаписывается на женский.

## API и миграция

`POST /onboarding/preferences` теперь требует `gender_target`. Это необходимое
уточнение контракта: старый запрос без этого поля не подтверждает выбор человека
и получает 422. Обновлённый Flutter отправляет поле после выбора. Прочие поля
и ранее требовавшийся пол в PATCH профиля совместимы. Пользовательские подсказки
направляют к параметрам, не показывают произвольный текст ошибки сервера.

Миграция 0027 снимает NOT NULL/default без подстановки данных и сохраняет ID,
размеры, ссылки и существующие значения. В старых строках невозможно достоверно
отличить прежний default unisex от осознанного выбора: такие значения сохраняются.
Миграция не является проверкой происхождения старых значений. При downgrade
наличие NULL вызывает отказ до изменений, а не автоматическое заполнение.
SQLite batch требует отдельного connection с FK OFF; FK ON отклоняется заранее.
PostgreSQL SQL проверен offline, миграция на живом PostgreSQL не запускалась.
