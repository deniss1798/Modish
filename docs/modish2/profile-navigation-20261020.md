# Профиль: навигация и читаемость — 20.10.2026

Профиль объединяет данные аккаунта и настройки персональной подборки. Он больше не повторяет основные вкладки приложения и не выдаёт длину загруженной очереди за количество товаров в каталоге.

## Что изменилось

- Компактная шапка: реальный email и имя из его адресной части. Настройки доступны по кнопке с явной подсказкой «Настройки». В низком широком окне шапка занимает одну строку.
- Основное действие — карточка «Параметры подборки». Она открывает прежний экран редактирования. Размеры верха, низа, платья/комплекта и обуви показаны отдельно; бюджет берётся из профиля. В широкой карточке бюджет расположен рядом с размерами.
- «Ваши предпочтения» открывают отдельный экран с источниками данных: выбор при знакомстве, стили и цвета по положительным конечным весам оценок, сценарии из параметров. Это обычный текст, а не кнопки. Неподдерживаемые служебные коды скрыты, одинаковые подписи не дублируются; анализ фото не подставляет стили по умолчанию.
- Блок «Магазины» содержит каталог и бренды. Каталог виден только при серверной возможности `catalogue_discovery_v1`; переход сохраняет обязательное отдельное согласие до загрузки товаров с непроверенными размерами.
- «Анализ по фото» остаётся необязательным действием. Текст не обещает гарантированного улучшения или доступной квоты; кнопка недоступна во время занятого состояния контроллера.
- Счётчики загруженной ленты и сгенерированных образов, а также дубли переходов «Мои образы»/«Сохранённое» убраны из тела профиля. Основные вкладки остаются в нижней навигации.

## Достоверность и границы сессии

Для нового `size_profile` показаны только явно подтверждённые значения соответствующих слотов. Неподтверждённый размер не заменяется старым общим полем. Если современного профиля размеров ещё нет, прежний размер одежды подписан именно «Одежда», а обувь показана отдельно. Неуказанный/нечисловой/бесконечный бюджет не подменяется значением по умолчанию.

Экран предпочтений отслеживает смену владельца/эпохи аккаунта и скрывает старые данные. Возврат из выбора бренда открывает поиск только в исходной сессии. Глобальное удаление маршрутов при смене аккаунта сохраняется без изменений.

## Проверка

`test/profile_navigation_test.dart` проверяет реальные переходы Flutter UI в окна 360×640 и 844×390, текст 130%, системные отступы сверху 24 и снизу 48 логических пикселей. В сценарий входят параметры, предпочтения, настройки, каталог с нулём запросов до согласия, принятие согласия, бренд → поиск и необязательное фото. Дополнительные проверки охватывают раздельные размеры, пустые данные, нечисловые веса/бюджет, инвалидацию аккаунта и блокировку фото во время запроса.

Для визуальной проверки тест с `--dart-define=PROFILE_NAV_CAPTURE=true` записывает только локальные синтетические данные и шесть PNG в `.tmp/profile-navigation-20261020/`: верх/низ профиля и подробности предпочтений в обеих ориентациях. Внешняя сеть и реальные аккаунты не используются. Эти снимки — проверка Flutter UI, не новая проверка на физическом Android и не свидетельство серверного развёртывания.

Финальные результаты после адаптации: 6/6 новых тестов прошли; scoped `dart analyze` — без замечаний. Ещё 20 существующих проверок `build11_ui`, `catalog_interactions`, `catalogue_discovery` прошли в первом совместном запуске; после него менялись только адаптивная компоновка шапки/карточки и новые тестовые scroll helpers. Все шесть свежих PNG просмотрены: переполнений, перекрытий кнопок навигацией и незавершённых переходов не обнаружено. Подробности предпочтений сняты после прокрутки до цветов; видимые обрезанные края карточек вверху относятся к положению прокрутки. Полный набор тестов и сборка выполняются отдельно корневой задачей.
