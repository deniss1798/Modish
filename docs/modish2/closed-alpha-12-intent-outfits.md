# 1.2 — Intent edits, образы и завершение онбординга

Локальный срез 16 октября 2026. Продолжает подготовку ленты и Style Swipe из
предыдущих срезов. Production, рабочие фиды, GitHub и APK не изменялись.

## Поведение

- Создание Intent теперь считает и одиночные товары, и комплекты в отдельной
  `REPEATABLE READ / READ ONLY` транзакции. Уточнение, замена части и feedback
  оставляют предыдущую версию целой до атомарной публикации следующей.
- Permanent dislike считается на чистом preview будущего Taste/User Twin,
  observed metadata, behavior и distinct product/day history. Событие относится
  к прежней версии Intent; событие, hidden state, Taste/Twin, существующий
  exposure, новая версия и метрики сохраняются одной транзакцией. Конфликт CAS
  или каталога откатывает их вместе. `too_expensive` и `not_for_context`
  сохраняют прежнюю семантику локального изменения задачи.
- Preview и запись используют общий чистый reducer и один captured clock.
  Overlay ограничен текущим Session/owner и снимается в `finally`.
  Legacy `build_feed_context` overlay не использует.
- Обычная сборка образов и три сценария WOW считают кандидатов без write-lock
  пользователя. Между фазами передаются frozen DTO, без ORM-объектов.
  Перед публикацией проверяются ревизия, профиль, правила источников, полные
  факты выбранных SKU, актуальное наличие, точные размеры и бюджет.
- Для истории образов учитывается соответствие `product_id → identity keys`.
  Одна общая сумма ключей недостаточна: перестановка алиасов между прежними
  образами не должна скрывать изменение проверки повторов.
- Сохранение/удаление из сохранённого и все писатели Outfit участвуют в ревизии
  входов. Публикация ротации меняет ревизию для следующего подбора, но не обучает
  Taste и не создаёт фактических просмотров.
- WOW сохраняет завершение, StyleProfile и образы атомарно. Повтор читает только
  выданный snapshot и повторно проверяет его факты; нет нового ранжирования или
  второго комплекта. Время ответа сериализуется в UTC независимо от timezone БД.
- Необязательная legacy-сборка после 20/30 событий выполняется после сохранения
  реакции и освобождения её соединения. Повторно проверяется отсутствие образов.
  Её ошибка не превращает уже принятую реакцию в ошибку запроса; неизвестный
  `total_events` возвращается как `null`, а не выдуманный ноль.
- Персональный текстовый поиск и «С чем носить» также используют отдельный
  snapshot и короткую проверку перед ответом. Поиск сохраняет literal filters,
  offset до 5000 и страницу до 200; он не получает скрыто exclusions ленты.
  Дополнения фиксируют полные факты исходной вещи, даже когда её нет в ответе.
  GET-публикация не пишет Taste, события, exposures, cache или allocation.

## Ограничения ресурсов и контрактов

У ranking отдельный cooperative budget 15 секунд; PostgreSQL получает остаток
через `statement_timeout`, Python проверяет deadline между товарами/пачками/
комбинациями. Одна Python-операция не прерывается принудительно. Deadline не
запускает второй дорогой расчёт. Изменение входов допускает один rerank, второй
конфликт даёт понятный 409 без частичных записей.

Блокировки каталога и его полные identity-проекции берутся до User-lock.
Публикация ограничивает ожидание блокировки 750 мс и SQL statement 2 секундами.
Это ограничения операций, а не измерение production p95.

Intent сохраняет прежнюю source-policy; SourceRule не добавлен туда скрыто.
Режим single/outfit, контракты размеров и суммы с копейками сохранены.
Неиспользуемые HTTP кодом compatibility-фасады продолжают владеть транзакцией
вызывающего кода. Legacy `/recommendations/generate` строит максимум десять
текстовых шаблонов из малого StyleProfile, без сканирования каталога.

## Проверки

Новые SQLite и настоящие HTTP/PostgreSQL проверки покрывают read-only rank,
непустые положительные комплекты, stock/price/dislike/Fit между фазами, rollback
после flush, grouped identity race, параллельное сохранение и два refresh,
единственного CAS-победителя feedback, единственное завершение WOW и его replay,
timezone, deadline и ошибки после durable feedback commit.

Приёмка текущего дерева, 16 октября:

- Backend: **837** тестов / 106,239 с, успешно; 47 PG opt-in пропущены в SQLite run.
- Все отдельные PostgreSQL: **47/47** / 49,843 с, успешно; 790 SQLite + 47 PG.
- Flutter analyze: без замечаний / 3,5 с. Flutter tests: **240/240**, 1:10;
  после этого Dart-код не менялся.
- Secret guard: 0 findings; `git diff --check` без замечаний.
- Изолированный workspace PostgreSQL остановлен; PID-файл отсутствует.

Пункт 1.2 закрыт на этих локальных критериях. Эти проверки не означают
production rollout, готовность всего ТЗ или измеренный p95 на телефоне.
