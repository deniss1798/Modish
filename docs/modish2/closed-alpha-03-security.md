15 октября 2026. Только код и изолированные проверки. Production, реальные
учётные данные, рабочие фиды, база и APK не изменялись.

## Учётные данные и CI

Guard проверяет рабочие tracked-файлы, staged blobs и новые неигнорируемые файлы.
Выводит только путь, номер строки и тип находки. Для private/env/SSH/key-файлов,
а также включённых в Git архивных/tmp-артефактов проверка завершается metadata
ошибкой, не открывая содержимое. История Git не переписывается.

Проверяются известные provider/token patterns, параметры credential URL и явно
заданные password/API/JWT/Admitad literals, включая короткие пароли и passphrase.
Исключаются целые значения явных placeholder, а не наличие слова `example`
внутри произвольного ключа. Нет общего исключения для папки тестов.
Это guard известных паттернов, а не доказательство отсутствия любого возможного
секрета в произвольном тексте.

Credential URL удалены из трёх конфигурационных шаблонов/примеров. Маркеры в
изолированных проверочных скриптах и тестах канонизированы как синтетические;
production controller/API semantics не менялись. Замороженные `release14*`
helpers не изменялись. CI запускает тесты guard и сам scan без новых зависимостей.

## Защита входа

POST `/auth/login`: 10 попыток/минуту/IP; POST `/auth/register`: 5.
Счётчики независимы от общего лимита; неуспешные попытки также расходуют квоту.
Ответ 429 содержит русский следующий шаг, `Retry-After` и `no-store`.
Поддельные forwarded-заголовки не меняют принятый `request.client.host`.
OPTIONS не расходует auth-квоту. Память ограничена TTL и числом активных клиентов;
новый IP не вытесняет активную квоту другого клиента.

ENV `AUTH_LOGIN_PER_MINUTE` допускает 1–60, `AUTH_REGISTER_PER_MINUTE` — 1–20.
Некорректные/отключающие значения отвергаются без вывода самого значения.
Это лимиты **на worker**, как и прежний общий limiter. Общий Redis limiter и
изменение доверия к reverse proxy в этот срез не входят. При развёртывании
нужно отдельно проверить фактический trusted client IP; заголовки не становятся
доверенными автоматически ради обхода общего IP прокси.

## Загрузчики

Общий `public_fetch` проверяет схему, userinfo, стандартный порт, публичность
всех DNS-ответов и IPv4/IPv6, включая адреса с вложенным IPv4. Приватный адрес
за разрешённым именем также отвергается. DNS ограничен 4 потоками, 8 ожидающими
операциями и 5 секундами ожидания. Зависшая системная DNS-операция удерживает
слот до фактического завершения; таймаут не открывает безграничную очередь.

HTTP соединяется с проверенным literal IP, сохраняя исходные Host и TLS SNI.
Каждый hop получает свежий client: TLS/cookies одного хоста не переиспользуются
для другого хоста на том же IP. Ambient proxy и автоматические редиректы
отключены. Разрешено не более четырёх редиректов, каждый адрес проверяется заново.
Для фидов HTTPS не понижается до HTTP. Медиа дополнительно требует HTTPS и
существующий список доменов магазинов.

Лимит проверяется до сохранения очередного куска, отдельно для encoded и
decoded тела: 12 МБ для фото, 256 МБ для фида. Oversized Content-Length
отвергается до чтения. Запрашивается identity; gzip поддерживается через
ограниченную распаковку. Chained/неизвестные encoding, повреждённый или
незавершённый gzip отвергаются. SVG/HTML не проксируются как фотография;
ответы медиа имеют `nosniff` и CSP sandbox.

Общий deadline медиа — 30 секунд, фида — 120. Он включает DNS, ожидание
заголовков, маленькие куски тела, редиректы и повторы. Внутренняя загрузка фида
асинхронна; прежний синхронный worker entry сохранён. Небезопасные URL/тела
не повторяются. Ошибка не импортирует частичный фид и не помечает каталог
отсутствующим на основании частичного ответа.

redirect loop, отсутствие Location, gzip-bomb, слишком большие тела,
медленные заголовки и отдача по одному байту, отмена, закрытие ресурсов,
