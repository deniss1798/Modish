# Shopping Intent: результат продолжения 9 октября 2026

Правки проверены на отдельной копии PostgreSQL. Рабочий API остаётся build13; новый APK не выпускался. Всё ТЗ ещё не завершено.

## Исправления

- Сборка начинает с проверки обязательных частей комплекта. Если обуви нужного подтверждённого размера нет, остальные полные карточки не загружаются и не ранжируются. Тип вещи перепроверяется после полного чтения.
- Повтор POST с тем же ключом возвращает исходную подборку, проверяя актуальность товаров. Он не ранжирует каталог заново, не пишет повтор generation и не перезаписывает context задачи.
- Замена исключает вещи, которые уже отклонены в этой задаче. Если доступных альтернатив нет, исходный комплект и версия сохраняются.
- Все 12 канонических событий из ТЗ подключены. Отдельные воронки intent/product/outfit считают уникальные запросы, товары и просмотренные комплекты. View не подменяется доставкой.
- Действия с частью образа и переход к продавцу относятся к выбранному outfit; принадлежность вещи проверяет сервер. «Дорого» и «не для задачи» учитываются как отказы в текущей выдаче, не меняя долгосрочный Taste.

В PostgreSQL-проверке использованы искусственные SKU с явными единицами размеров. Она доказывает контракт API/аналитики, не наличие полных образов в реальном каталоге. В первом запуске тестового скрипта не было flush между имитациями API-запросов; затем после savepoint rollback не были повторно созданы товары следующего сценария. Ошибки скрипта исправлены, финальный прогон прошёл; исходные журналы сохранены. Коммитов тестовых данных не было.

На копии реального каталога измерены три последовательных запуска каждой задачи для профиля LETTER L. При ограничении 0,75 CPU / 768 МБ пустой office/wedding intent ускорился с 22–23 до примерно 5–6 секунд. В v18 зафиксированы 5,61 с для office и 5,29 с для wedding; source composition/eligibility в v19 совпадает с v18. Это не production p95, не нагрузочный тест и не доказательство скорости непустых комплектов.

## Осталось

1. Подтвердить размерные системы и наличие вариантов источников. RU-профили и обувь пока не дают достаточного точного покрытия.
2. Получить и визуально проверить реальные полные образы; их отсутствие не считается успехом.
3. Ускорить холодную колоду/первую ленту; предыдущий smoke v16 измерял 11–13 секунд первой ленты.
4. Выполнить согласованный выпуск API/клиента и выдать новый APK после прохождения проверок каталога.
