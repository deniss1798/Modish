# 3.1 — причины отказов в аналитике первой сессии

Локальный срез 18 октября 2026. Без production deployment.

У существующего административного `/analytics/first-session` сохраняются
показатели первых20 уникальных показанных карточек, union Like/Save,
открытия товара/магазина и достижение десятой карточки. Добавлен
`dislike_reasons`: число текущих отказов, число карточек с причиной/без неё
и упорядоченные `top_reasons` с количеством и долей.

Знаменатель причин совпадает с текущими отказами исходной метрики. Повторные
события не создают новые карточки; изменение dislike на like/skip убирает
карточку из этого среза. Для одной карточки берётся последняя принятая причина
после её показа. Владелец и product ID сопоставляются вместе. Style Swipe,
отдельный каталог, серверная выдача/prefetch и произвольная телеметрия
не добавляют причин. Срез использует durable RecommendationEventV2 и
ActivationExposure, а не клиентский MetricEvent.

В ответе допускаются только известные коды причин. Неизвестный исторический
текст, отсутствующая причина и повреждённый metadata JSON учитываются в
`without_reason_cards`; сырые строки не выдаются и не становятся измерениями.
Старые карточки без соответствующего event не теряются из знаменателя.

У первой реакции может не быть отдельного предшествующего view. При создании
exposure используется время того же принятого события: иначе первый dislike
ошибочно выглядел бы случившимся до показа из-за разницы в несколько микросекунд.
Старые вызывающие функции сохраняют совместимость с необязательным временем.

Клиент уже отправляет ограниченные коды причин либо отказ без причины;
новый UI и свободный текст для аналитики не добавлялись.

Окно отчёта и поле `days` теперь используют одинаковую границу 1–90 дней.
Некорректные будущие завершения, позиции за пределами первых20 и показы
до завершения онбординга не входят в знаменатель.
