## Оценка

План подходит для тестирования сначала на 10–15 людях, затем до 50: он ставит
точность размеров, честность и надёжность перед новыми функциями.
Часть основы уже есть: exact resolver, жёсткая admission policy, фото reservations,
аналитика реальных первых20 просмотров и отдельный честный каталог.
Проверять нужно реальные обходы и критерии, а не переписывать готовые компоненты.

## Границы доказательств

«0 неправильных размеров» проверяется на фиксированных данных и сценариях,
с непустыми положительными примерами, а не пустой выдачей для всех.
Browse-каталог на10 профилях не равен персональной первой сессии.
Unknown units остаются вне персональных рекомендаций.

Код не гарантирует наличие в магазине после изменения фида или checkout.
Обувные данные и достаточность SKU для полных комплектов — внешняя зависимость.
Нужны подтверждённые системы, реальные наблюдения наличия и honest empty.
Скорость первой сессии измеряется по этапам на контролируемой конфигурации;
неизмеренные production p95/поведение физического телефона не считаются пройденными.

Кодовые пункты 0.1–2.2 и 3.1–3.3 закрыты на указанных локальных критериях.
Пункт2.3 остаётся внешней зависимостью по согласованному с пользователем порядку.
Актуальная [итоговая сводка](closed-alpha-local-summary-20261019.md) отделяет
проверенный код от неподтверждённой готовности рабочего каталога/телефона.
Дополнительно [проверен настоящий Android UI с локальным HTTP](closed-alpha-34-device-journey.md):
исправлена потеря возможностей после онбординга, полный путь прошёл на
эмуляторе с новой синтетической БД. Это не проверка рабочего ассортимента.

Definition of Done всего ТЗ пока **не достигнуто**: реальная первая сессия на
рабочих товарах и физическом телефоне не подтверждена локальными fixtures.
Готовность выдавать реальные инвайты не следует из числа зелёных тестов.
