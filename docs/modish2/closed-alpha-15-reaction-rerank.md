# 1.5 — обновление вкуса после десяти реакций

Локальный срез 18 октября 2026. Значимыми считаются подтверждённые
`like/save/dislike/skip`; view/open/affiliate и повторный `idempotent` save
не заменяют эти сигналы.

Сервер уже читает текущие Taste/User Twin в новом snapshot на каждом запросе
ленты, то есть не ждёт десятого события. Отдельный серверный порог или фоновая
ML-задача для этого не требуются. HTTP-интеграционная проверка использует
десять настоящих POST реакций и последующий GET, без подмены scoring/cache.

На клиенте счётчик раньше изменялся после метрик и дополнительного GET
сохранённого. Ошибка этого GET теряла уже подтверждённую реакцию, а
`idempotent` ответ мог считаться ещё раз. Принятая реакция теперь учитывается
сразу после POST и проверки сессии. Вспомогательная телеметрия/обновление
сохранённого не отменяют её и не определяют завершение пользовательского действия.

Общий локальный callback учитывает постоянные реакции из Intent без второго
POST. Причины `too_expensive/not_for_context` меняют только задачу и не считаются
обучением глобального вкуса. Callback защищён поколением задачи и аккаунта;
reload после конфликтного 409 сам по себе не является новой реакцией.

Каждая десятая подтверждённая реакция пересчитывает оставшуюся очередь в фоне.
Текущая карточка сохраняется, просмотренные идентичности исключаются; поздний
ответ прошлого расчёта/аккаунта не подменяет новый. Ошибка фонового расчёта
сохраняет пригодную очередь.

## Приёмка

Три новые backend проверки используют настоящие FastAPI HTTP запросы на
изолированной SQLite БД. В первой и warm legacy ленте две неизменные карточки
с одинаковыми размером, ценой, категорией и качеством меняют относительный
порядок после десяти смешанных реакций. Обе остаются в пуле: изменение нельзя
объяснить только исключением оценённых вещей. Проверены durable Taste/User Twin,
ровно десять новых событий/ревизий и отсутствие повторного обучения при save replay.

27 новых Flutter проверок покрывают десятый/двадцатый ответ, смешанные сигналы,
ошибку POST, idempotent save, подробности товара, Intent, task-only причины,
409 reload, задержанные метрики/сохранённое, смену аккаунта и dispose.
